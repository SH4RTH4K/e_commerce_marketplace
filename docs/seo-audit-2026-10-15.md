# TAQI LIFE SEO audit — 15 October 2026

## Scope and evidence

Reviewed the live category listing and its rendered metadata, public HTTP responses,
catalogue and information-page controllers, server-rendered HTML, client navigation,
product pricing/stock, category hierarchy, sitemap, robots rules, and configured social links.
Existing category/product SEO text is preserved; this release does not edit catalogue records.

Before the release, `/category/mens-fashion?page=2` had a first-page canonical,
`noindex,follow`, no pagination anchors, no structured data, and both a hidden site H1
and the visible category H1. These findings were confirmed in the live browser.

## Application fixes

- Unfiltered listing pages, including later pages, are indexable and use their own
  canonical URL. Tracking parameters do not make them non-indexable. Search, filter
  and sort views remain `noindex,follow`. Out-of-range pages return 404.
- Load More exposes a real next-page link while retaining incremental loading.
  Initial HTML also includes a useful no-JavaScript catalogue and pagination links.
- Product and nested breadcrumb JSON-LD are present in initial HTML and update on
  Inertia navigation. Offers use actual BDT customer prices (including zero prices)
  and the same stock rule as the storefront. No ratings or reviews are invented.
  Products with variant price adjustments omit offers until complete variant offers
  can be described accurately; their product identity and breadcrumbs remain available.
- Home/About business identity uses OnlineStore and WebSite markup, the configured
  logo/contact details and existing social URLs. No physical address is invented.
- Information pages receive distinct titles/descriptions; known page aliases share
  the canonical information-page URL. Existing product/category metadata takes precedence.
- Social cards have a logo/category-image fallback. Hidden duplicate H1s move into
  a visible no-JavaScript fallback instead of appearing alongside React page headings.
- Private/admin/cart/checkout/account/order/authentication pages receive noindex
  response headers and initial HTML metadata. Robots exclusions continue to apply.
- Sitemap includes public information pages, excludes categories with inactive,
  orphaned or cyclic ancestor paths, and refreshes after relevant product/category
  changes. A versioned cache prevents deployment serving the previous sitemap.
- `llms.txt` uses complete product URL keys including SKU and handles zero prices.
- Page components load on demand. The main production JavaScript asset decreased
  from approximately 2,047 KB to 329 KB uncompressed. Page/shared chunks still load
  as needed; this is a bundle-size comparison, not a measured Core Web Vitals result.

## Validation

63 focused PHP tests passed (735 assertions), 39 component tests passed, and the
production build completed. New HTTP tests cover pagination/canonical/indexing,
no-JavaScript links, schema pricing/stock, hierarchy, script escaping, private-page
headers, saved metadata preservation, sitemap validity and SKU-based crawler links.

## External work requiring account access

Fresh unauthenticated requests to the homepage, products, `robots.txt`, `sitemap.xml`
and `llms.txt` returned HTTP 200 with an HTML hosting verification page instead of
the requested document. Chrome subsequently reached the store. This establishes a
challenge for these audit requests; it does not establish how verified Googlebot
is treated. Hosting must check verified search crawlers and Search Console live
URL inspection before changing any firewall rule. Do not disable protection broadly.

Search Console ownership, index coverage, crawl statistics, submitted sitemaps and
backlink reports could not be verified without the owner's property access. A
focused public domain search is not a complete backlink audit. Facebook, Instagram
and YouTube URLs exist in the store; external fetches were throttled, so profile
ownership, descriptions and reciprocal website links remain unverified. No outreach,
social publication, backlink purchases or account changes were performed.

Owner steps: open Search Console with the business Google account, select
`taqilife.com` or `https://taqilife.com/`, inspect a live product/category URL, check
Settings → robots.txt/Crawl stats and the sitemap submission. Hosting panel access
is usually provided in the hosting purchase/welcome email. Ask hosting support to
check the verification responses for verified Googlebot/Bingbot and crawler files.
